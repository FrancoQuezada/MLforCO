Executive summary
The current manuscript has a publishable core, but it should be repositioned more carefully.
The paper should not be framed as a broad solution to “machine learning for combinatorial op-
timization.” Instead, it should be presented as a small-data, feasibility-aware matheuristic
for repeated operational 0-1 MILPs. The central idea is strong: learn binary decisions from
solvedinstances,projectthepredictionintoafeasiblebinaryvectorusingaPhase-I-inspiredrule,
and solve the resulting restricted MILP.
The next stage should not start by adding a much more complex learning method. The
priority is to prove, through a clean ablation study, which components are responsible for the
observed performance. After that, the team can decide whether to add a second 0-1 MILP class
and whether to include a regret-aware extension.
Recommended order:
1. Reposition the paper and narrow the claims.
2. Reproduce the current MCLSP results with clean scripts.
3. Build the ablation table and report feasibility, gap, runtime, and number of flips.
4. Add robustness tests across random seeds, training sizes, and instance difficulty.
5. Add a minimal regret-aware experiment: select models by validation objective regret, not
only by classification accuracy.
6. Only then decide whether to add a second 0-1 MILP problem class.

1. How to reposition the work
1.1. Current risk
Themanuscriptcurrentlystudiesapredict-then-optimizeframeworkfor0-1MILPsandtests
itontheMulti-itemCapacitatedLot-SizingProblem(MCLSP).Itusesclassicalmachinelearning
models, feature sets based on model parameters and linear relaxations, and a feasibility-aware
discrimination rule inspired by Phase I of the simplex method. In the strongest setting, the
reported results show very large runtime reductions and small optimality gaps.
The risk is that reviewers may interpret the paper as making a broad claim about machine
learningforcombinatorialoptimization,whiletheevidenceismostlybasedononeproblemclass
and one strong feature family. A reviewer may ask:
Is the improvement due to machine learning, or mostly due to the strengthened linear
relaxation?
Is the feasibility-aware rule essential, or would simple rounding and repair give similar
results?
Does the method generalize beyond MCLSP?
1.2. Recommended positioning
The paper should be framed as follows:
We study whether a feasibility-aware projection of ML-predicted binary decisions can
produce reliable small-data matheuristics for repeated operational 0-1 MILPs.
This positioning is stronger because it emphasizes what the paper actually does well:
It uses small training sets.
It preserves feasibility before solving the restricted problem.
It is useful for repeated operational decision-making.
It evaluates runtime-quality tradeoffs rather than pure prediction accuracy.
1.3. Possible titles
A feasibility-aware small-data matheuristic for repeated 0-1 operational MILPs
A feasibility-aware predict-then-optimize matheuristic for operational MILPs
If the paper remains MCLSP-only: A feasibility-aware predict-then-optimize matheuristic
for capacitated lot-sizing
1.4. Reformulated contribution statement
The contribution should be written in a controlled way:
1. We propose a feasibility-aware discrimination rule that transforms continuous ML scores
into feasible binary decisions through a single auxiliary optimization problem.

4. Ablation table: purpose and structure
An ablation table removes or replaces one component of the method at a time. The goal is
to show not only that the full pipeline works, but why it works.
The full method contains several components:
1. A source of prediction scores z for the binary variables.
2. A feature set: A, B, or C.
3. A classification threshold.
4. The feasibility-aware discrimination rule.
5. A restricted MILP obtained by fixing the predicted binary vector.
6. A post-processing step that removes unnecessary setup activations.
The ablation table should compare variants that isolate each component.

5. Experiments needed to build the ablation table
5.1. Experiment 0: reproducibility and clean pipeline
Objective. Ensure that the current results can be reproduced from clean scripts.
Tasks.
1. Createasingleconfigurationfiledefininginstancesize,capacityratio,randomseed,feature
set, ML model, solver time limit, and output folder.
2. Save all generated instances with unique identifiers.
3. Save the optimal or best-known solution for every instance.
4. Save feature-generation time, training time, prediction time, repair time, restricted MILP
time, and total time separately.
5. Reproduce the current tables for feature sets A, B, and C.
Output. A reproducibility table confirming that the current manuscript results can be rege-
nerated.
5.2. Experiment 1: baseline comparison
Objective. Establish fair reference points.
Methods to compare.
Full Gurobi solve with the same time limit used in the manuscript.
Threshold-only ML prediction.
LP rounding using feature set B or C values as scores.
LP rounding plus feasibility-aware rule.
Gurobi warm start from the predicted solution, if easy to implement.
Full proposed method.
Output. A table showing feasibility rate, objective gap, runtime, and number of solved
instances.
5.3. Experiment 2: feasibility rule ablation
Objective. Prove that the Phase-I-inspired rule is necessary and useful.
Procedure.
1. Generate raw ML predictions using z ≥β.
2. Check whether the restricted MILP with this raw binary vector is feasible.
3. Apply the feasibility-aware rule.
4. Record how many variables are flipped.
5. Solve the restricted MILP after repair.

6. Compare objective value and runtime before and after repair.
Metrics.
Raw feasibility rate.
Repaired feasibility rate.
Mean and maximum number of flips.
Repair time.

5.4. Experiment 3: feature-set ablation
Objective. Quantify the role of feature sets A, B, and C.
Procedure.
1. Fix the ML model, preferably RF if it remains the best model.
2. Train the model separately with feature sets A, B, and C.
3. Apply the same threshold, same repair rule, and same restricted MILP procedure.
4. Compare accuracy, feasibility, objective gap, runtime, and flips.
Interpretation. If feature set C dominates, the paper should not hide this. Instead, the
contribution becomes: strengthened relaxations generate informative signals, and the feasibility-
aware rule turns those signals into reliable feasible decisions.
5.5. Experiment 4: post-processing ablation
Objective.Measurewhetherremovingunnecessarysetupactivationsimprovestheobjective.
Procedure.
1. Solve the restricted MILP after the feasibility-aware rule.
2. Identify binary setup variables fixed to one but associated with zero production.
3. Remove these unnecessary setups.
4. Recompute objective value.
Metrics.
Number of removed setup variables.
Objective improvement from post-processing.
Frequency with which post-processing changes the solution.

5.6. Experiment 5: robustness across seeds and splits
Objective. Show that the method is not an artifact of one split.
Procedure.
1. Use at least 10 random seeds.
2. Ensure splits are made at the instance level, not at the row or variable level.
3. Report mean and standard deviation for all key metrics.
4. If possible, report 95% confidence intervals.
Output. A robustness table with mean ± standard deviation for GapObj, GapTime, feasi-
bility rate, and flips.
5.7. Experiment 6: training-set size sensitivity
Objective. Support the small-data claim.
Procedure.
1. Trainwithdifferentnumbersofsolvedinstances,forexampleN ∈{6,9,12,18,24}ifcompu-
tationally feasible.
2. Keep the test set fixed.
3. Evaluate how solution quality and feasibility evolve as training data increases.
Expected insight. If performance is already strong with few instances, this reinforces the
main story of the paper.
5.8. Experiment 7: instance difficulty and scalability
Objective. Identify when the method is most valuable.
Factors to vary.
Number of items.
Planning horizon.
Capacity tightness.
Setup-to-holding cost ratio.
Output. A table or heatmap showing where the proposed method has the best runtime-
quality tradeoff.

The paper should include two types of comparisons.
7.1. Computational baselines
These are methods to implement and run:
Full MILP solver with time limit.
LP rounding.
LP rounding plus feasibility-aware rule.

Optional: solver warm start from predicted variables.
7.2. Literature positioning
These methods do not all need to be reimplemented, but they should be discussed clearly:
Predict-then-optimize and decision-focused learning methods, especially SPO and SPO+.
Neural diving and neural branching approaches for MIP.
Learning-based variable fixing and correction methods.
Lot-sizing ML approaches, especially LSTM or transformer-based methods for setup pre-
diction.

on all benchmarks. Its niche is small-data, interpretable, feasibility-aware, operational
MILP matheuristics.

8. Regret-aware extension
The current ML models are trained to reduce prediction error in the binary vector. However,
not all binary mistakes have the same downstream cost. In MCLSP, predicting a setup variable
incorrectly can have very different consequences depending on item, period, demand, capacity,
and cost structure. A false negative may make the restricted problem infeasible. A false positive
may only add an unnecessary setup, and it may later be removed by post-processing. Therefore,
standard accuracy is not fully aligned with optimization performance.
8.1. Core idea
The regret-aware extension asks:
Can we train or select ML models by the cost of the optimization error they induce,
rather than by the number of binary variables they classify correctly?

8.2. Minimum viable regret experiment
The easiest useful version is not to change the training algorithm yet. Instead, change the
model selection criterion.
1. Train the same candidate ML models and hyperparameters as before.
2. On the validation fold, apply the complete optimization pipeline: prediction, feasibility
rule, restricted MILP, post-processing.
3. Select the model that minimizes validation GapObj or validation regret.
4. Compare this against the current accuracy/CV-based selection.
This directly tests whether a model with lower classification accuracy can produce better
optimization decisions.
8.3. Second-level regret-aware variant: weighted classification
After the minimum experiment, we can try cost-weighted training. Instead of treating all
binary variables equally, assign a weight w to each binary label y , where w estimates the
ip ip ip
cost of misclassifying variable p in instance i.
Possible weights:
Exact counterfactual weight: solve the model after forcing one variable to the wrong value
and measure objective degradation. This is accurate but expensive.
Approximate weight from objective coefficients, setup costs, demand, capacity tightness,
or reduced costs.

Then train using weighted classification, for example through sample weights in random
